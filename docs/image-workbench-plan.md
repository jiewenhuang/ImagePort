# ImagePort 图片工作台收敛计划

整理日期：2026-11-07

技术方向已确定：继续使用 Tauri 2、SvelteKit 2 / Svelte 5、TypeScript、Tailwind CSS 4、SQLite 和 Rust HTTP bridge。

本轮已按此方案实施图片主线收敛：完成源码/运行数据归档，移除 Studio 与视频/S3 的活跃实现，加入设置 v2 兼容迁移，并完成任务控制、设置面板和历史媒体按需读取的首批整理。

具体变更和兼容说明见 [升级说明](image-workbench-upgrade.md)，检查结果、性能测量方法及尚未验证的范围见 [验收记录](image-workbench-validation.md)。后续结构整理继续采用小批次方式，优先保持图片主流程稳定。

## 1. 产品边界

目标定位：本地优先的 AI 图片生成、编辑与管理工作台。用户可以从提示词和参考图开始，生成图片、局部修改、反复迭代，并保存可追溯的历史。

本次方案按 Studio 整体退出主线安排，包含剧本、角色制作流程、分镜、视频生成、Take 管理、时间轴及成片导出。角色参考和一致性中可用于普通图片编辑的实现先评估复用，不扩展成新的项目系统。

| 范围 | 处理方式 |
| --- | --- |
| Gallery 生图、改图、多参考图、蒙版 | 保留并完善 |
| 图片 Provider、模型能力、原生协议、自定义同步/轮询协议 | 保留，继续按图片能力维护 |
| Agent | 保留图片创作相关的对话、生成、编辑、停止和继续能力 |
| 历史、收藏、检索、批量操作、下载、备份恢复 | 保留 |
| Studio 和视频 Provider、视频任务轮询、视频落盘、FFmpeg 导出 | 分阶段退出 |
| S3 | 当前调用主要服务 Studio；确认引用后随 Studio 退出主流程，归档已有配置 |
| 角色一致性、提示词模板等可选增强 | 待核心流程稳定后按实际使用需求评估 |

主界面围绕图片历史/收藏、生成与编辑输入区、结果预览组织。Agent 作为图片辅助模式，蒙版和大图预览按需打开。设置保留 API 连接、图片/Agent 路由、生成偏好、本地数据和通用设置。

## 2. 实施前的代码事实

- `src/routes/+page.svelte` 同时挂载 Gallery 和 Studio，使用 CSS 控制显示。
- Studio 挂载时读取项目并尝试恢复视频任务，隐藏入口无法停止这些初始化行为。
- Studio/视频依赖已经进入公共 `settings.ts`、设置界面和 Gallery 数据库初始化。
- 现有完整备份格式包含 Gallery 任务、图片、蒙版、partial images、设置和 Agent 会话，没有包含 Studio 项目与视频素材。
- Studio 存在独立 SQLite、共享数据库旧表、localStorage 旧格式以及本地媒体路径，需要一起核对。
- Gallery 已有分页和缩略图。后续性能工作应检查每页水合读取的原图、输入图和蒙版，避免重复实现已有能力。
- `GalleryWorkspace.svelte` 约 2804 行，`GallerySettingsModal.svelte` 约 1525 行，适合在行为稳定后按职责拆分。
- 工作区有大量已修改及未跟踪文件，实施应以当前工作区为基线。

## 3. 阶段 0：建立基线与可恢复归档（P0）

### 工作

- 建立包含已修改、未跟踪文件的源码快照，记录当前变更；运行数据与密钥通过独立的本地归档保存。
- 运行现有测试、类型检查、前端构建和 Rust 检查，记录已有失败，区分后续变更新增的问题。
- 在关闭应用或使用一致性备份方法后归档数据库、设置、图片目录、Studio 媒体和相关旧格式数据；处理 SQLite WAL，确保快照可读取。
- 核实 `imageport.db`、`imageport-studio.db`、两处数据库的 Studio 表、Studio localStorage 格式和媒体实际路径。
- 使用数据副本验证归档可恢复；Gallery ZIP 备份与 Studio 归档分别核验覆盖范围。
- 使用固定样例记录启动时间、空闲内存、历史首屏加载时间和安装包大小，注明平台与构建方式。

### 验收

- 当前源码和历史数据都有可恢复副本。
- 有现有检查结果与性能基线。
- 已知哪些数据由现有 ZIP 备份覆盖、哪些需单独归档。

## 4. 阶段 1：收敛入口与运行行为（P0）

### 工作

- 移除主导航的 Studio 入口以及根页面的 Studio 挂载和设置返回逻辑。
- 移除设置中的视频连接、Studio 剧本/图片/视频路由和 Studio 专用存储配置。
- 保留 Gallery、Agent 的独立模型选择和图片路由。
- 停止 Studio 自动初始化、项目写入和视频任务恢复。
- 简化页面标题、空状态、帮助文字和定位说明，统一为图片工作台。

### 验收

- 冷启动不加载 Studio 项目、不恢复视频任务、不请求视频 Provider。
- 生图、改图、Agent 和设置仍正常使用。
- 产品主流程中不再出现视频专用入口和配置。

## 5. 阶段 2：清理实现与兼容旧数据（P0）

### 工作

- 按引用清理 `components/studio`、`domain/studio`、`lib/video`、Studio runners、Studio 存储/命令包装及专用测试。
- 清理 Rust 视频下载、视频地址探测、FFmpeg 命令注册和专用模块。
- 核对 S3 的实际调用；在没有图片主流程依赖时退出其 UI、命令和服务。
- 按实际引用清理 Cargo 依赖/feature、前端依赖、Tauri capabilities 与 asset scope。
- 保留图片 HTTP、multipart、流式、取消、下载等通用能力，以及图片自定义 Provider 需要的轮询逻辑。
- 为设置添加明确的格式版本与兼容归一化：保留图片/Agent 配置和凭据，兼容导入旧设置中的 Studio 字段，停用字段不进入运行逻辑。
- 核对共享 API Profile，保留仍被图片或 Agent 使用的连接。
- 停止创建 Studio 专用表，已有表和素材留在归档/原存储中；功能退出不触发自动删表、删媒体或历史清理。
- 代码归档由源码快照承载，发行产物只包含当前产品需要的实现。

### 验收

- 运行代码中没有视频/Studio 活跃依赖，专用权限和构建依赖按引用清除。
- 旧设置、旧 Gallery 历史和旧 ZIP 备份仍能读取。
- 升级、再次启动、旧设置导入不会重新启用 Studio 或丢失图片配置。
- 历史任务、Agent 会话和图片文件不受功能收缩影响。

## 6. 阶段 3：整理图片主线架构（P1）

### 工作

- 在现有领域模块基础上拆分 Gallery 的任务控制、Agent 会话、历史/收藏、参考图与蒙版、导入导出职责。
- 将设置按连接、图片/Agent 路由、生成偏好、数据管理拆分，减少超大组件中的状态耦合。
- 明确 UI、任务编排、Provider、存储、Tauri 接口的依赖边界；沿用现有依赖注入方式。
- 统一任务从排队、请求、接收 partial 到完成/失败/取消的状态处理。
- 任务生命周期独立于界面切换，避免切换模式造成重复提交、丢失结果或错误取消。
- 一批只迁移一类职责，保持可运行，并复用已有领域测试验证行为。

### 验收

- 主组件负责组合与交互，不再集中承担所有请求、会话和存储操作。
- 切换 Gallery/Agent、打开设置和预览不会重复提交任务。
- Provider 协议行为和已有图片/Agent 路由保持兼容。

## 7. 阶段 4：完善核心体验与性能（P1）

### 图片流程与可靠性

- 核验拖入、文件选择、粘贴参考图、重复输入处理以及按模型能力校验参数。
- 完善“查看结果 → 作为参考继续修改 → 保存历史”的连续操作，保持提示词、模型、参数、参考图和蒙版可追溯。
- 验证流式 partial、最终图片、失败、取消和重试的状态转换；取消后的迟到结果不覆盖任务终态。
- 重试由用户操作触发，明确请求范围，避免多图任务重复提交已完成的部分。
- 重启后明确标记中断任务，不自动重发付费生成请求。
- 核验蒙版坐标、透明度、导出尺寸、图片复制、单图/批量下载及大图预览。

### 数据与性能

- 保留现有分页，列表以元数据和缩略图加载；原图、参考图和蒙版按详情、复用、下载等实际需求读取。
- 图片引用与图片内容分离，减少大图反复转为 base64 及跨层传递的次数；按实测决定是否改用受限文件 URL 和缓存。
- 统一取消/结束时的请求、监听器和预览资源释放。
- 历史删除、收藏和批量操作后，文件引用及持久化状态保持一致。
- 用与阶段 0 相同的数据、平台和构建配置对比启动、内存与历史加载；仅在证据需要时引入列表虚拟化或进一步缓存。

### 验收

- 无参考图生图、多参考图编辑、蒙版编辑、Agent 图片迭代、取消和重试均跑通。
- 大量历史不会在启动时读取全部原图；列表首屏与滚动表现有对比记录。
- 文件缺失、请求中断、数据库异常有可理解的反馈，并可恢复继续使用。

## 9. 执行批次与完成标准

| 批次 | 内容 | 本轮状态 |
| --- | --- | --- |
| A | 阶段 0 | 源码/数据归档及逐文件校验、现有检查基线完成；冷启动与空闲内存测量待补 |
| B | 阶段 1–2 | Studio/视频/S3 活跃实现退出、设置 v2 兼容和依赖清理完成 |
| C | 阶段 3 | 任务控制、媒体读取、公共任务构建与结果处理、偏好和数据设置面板首批提取完成；其余大组件继续分批整理 |
| D | 阶段 4 | 按需读取与真实历史 I/O 对比完成，原生模拟接口核心流程通过；真实网关及系统交互完整矩阵待补 |
| E | 阶段 5 | 自动检查、macOS Apple Silicon 本地安装包和升级/验收文档完成；跨平台、签名、公证及发布另行推进 |

B 是本次功能收缩的最小可交付版本，必须先通过数据兼容和核心图片流程检查，再进入后续整理。C 和 D 按小改动推进，避免结构调整与大量体验变化混在一起。

本轮完成的判断：主流程只围绕图片，Studio 无后台活动和活跃依赖；旧图片数据兼容；核心图片操作完整；检查与实际打包验证有记录。后续新增能力以是否改善图片生成、编辑和管理为准。
